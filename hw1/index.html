1. Introduction and Mathematical Specifications

The objective of this assignment is to conceptually demonstrate how public-key cryptography based on elliptic curves (ECC) operates. Elliptic-curve scalar multiplication acts as a cryptographic One-Way Function (relying on the Elliptic Curve Discrete Logarithm Problem - ECDLP).

To fully understand the underlying mechanics without relying on abstracted libraries, an interactive application has been implemented based on a Toy Curve defined over a small finite field $\mathbb{F}_{17}$.

  • Curve Equation: y² ≡ x³ + 7 (mod 17)
  • Base Point (Generator): G = (1, 5)

2. Implementation Details (Background Algorithm)

This web application does not use any external cryptographic libraries. The entire modular arithmetic required for point addition on the projective plane has been implemented from scratch in JavaScript. Below is an excerpt of the core logical implementation operating behind the scenes:

4. Statistical Exploration

By repeatedly performing empirical experiments on the algorithm for different values of k, the following fundamental properties of the generated cyclic group can be observed.

Uniform Distribution and Apparent Randomness

Observing the graphical representation, the valid generated points (x, y) do not follow a smooth, continuous geometric interpolation (as they would in the reals $\mathbb{R}$), but rather distribute in a scattered, seemingly random pattern across the discrete plane. This behavior guarantees the absence of easily reversible spatial patterns, a fundamental property for preserving the hardness of the ECDLP.

Cyclic Nature and Frequency of Values

The analysis shows that the point 18G yields the Point at Infinity ($\mathcal{O}$), and 19G returns to (1, 5). The generated subgroup has an order of 18 (a result consistent with Hasse's Theorem). Every value within the finite domain appears with a frequency of exactly 1 per cycle: there are no collisions before the orbit (period) is fully completed.

Correlation and "Avalanche-like behaviour"

In ECC, moving from k=6 to k=7 entails algebraically adding the generator G to the current point. The Euclidean distance between the two consecutive outputs is highly unpredictable. However, this is a strongly algebraic (homomorphic) correlation, completely different from the true "Avalanche Effect" performed by Hash functions (where one flipped input bit statistically flips 50% of the output bits regardless of linear arithmetic).

Cryptographic One-Way Function vs Hash Function

Based on these findings, the architectural distinction becomes clear:
Hash Functions (e.g., SHA-2) compress data of arbitrary length into a fixed-size output devoid of exploitable mathematical structure. They provide collision and pre-image resistance, acting like random oracles.
ECC Scalar Multiplication, instead, maps a fixed-size input (a 256-bit scalar) to a fixed-size domain (256-bit coordinates). It is deterministic and computationally intractable to reverse (One-Way), but its purpose is to possess a precise algebraic "trapdoor" that allows for complex interrelated calculations (such as ECDSA/Schnorr Digital Signatures)—an operation mathematically impossible with a simple Hash.
