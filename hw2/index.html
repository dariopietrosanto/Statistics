1. Objective of the Assignment

This section examines the Practical Cryptographic Pipeline adopted in Ethereum Wallets (such as MetaMask or Rabby) for generating a public address starting from a mnemonic phrase. The architecture, which combines various cryptographic algorithms (Key Derivation, Hashing, Public-Key Cryptography), will be discussed, providing engineering justification as to why the system requires multiple primitives in succession rather than a single universal algorithm.

3. Analysis of Cryptographic Primitives (Why separate systems?)

Each step serves a radically different engineering and statistical purpose. A single "universal" algorithm could never simultaneously satisfy the requirements of User Experience (UX), mathematical hierarchy, asymmetric derivation, and fixed-size compression.

Key Generation vs Key Derivation (BIP-32/39/44)

Generation provides pure entropy (pseudorandom statistics) by producing the initial seed (BIP-39). Derivation (BIP-32/44), on the other hand, is a deterministic tree-like process that uses HMAC hashing functions to generate infinitely many sub-accounts (Private Keys) from that single root. It selects a specific key in the probability space without exposing the root.

Public-Key Cryptography (secp256k1)

Once the Private Key is derived, secp256k1 (ECC) allows for the calculation of the associated Public Key by leveraging modular arithmetic (Scalar Multiplication). This step is necessary to enable Digital Signatures, introducing the vital asymmetric "trapdoor" mathematical relationship required to authorize transactions on the blockchain.

Hashing (Keccak-256)

The raw Ethereum Public Key consists of 64 bytes. Keccak-256 performs the final scrambling, deterministically compressing it to extract only the resulting last 20 bytes. This removes the algebraic structure of the elliptic curve, offering pre-image resistance and drastically reducing on-chain storage costs (gas).

Checksums and Encoding (EIP-55)

The final step has no purely cryptographic value but serves application security. EIP-55 maps the Keccak-256 hash of the address onto the address letters themselves: if the n-th bit of the hash is 1, the corresponding letter is capitalized. It acts as a statistical Checksum that catches typing errors with an extremely negligible false positive rate.

4. Historical and Chronological Context (Timeline)

The technologies adopted in the Ethereum ecosystem reflect standardized layers built over decades of cryptographic evolution.

1977 | RSA Introduction of modern asymmetric cryptography (Public-Key Cryptography). Based on prime factorization, it laid the foundation for modern digital signatures, although it has now been superseded (in blockchain) by elliptic curves.
2001 | SHA-2 / SHA-512 NIST standardizes the new families of Hash functions. Highly resistant to collisions, they still dominate Bitcoin's Proof-of-Work (PoW) today.
2012 | BIP-32 The advent of Hierarchical Deterministic Wallets, making it possible to manage an infinite hierarchical tree of keys starting from a single Master Node.
2013 | BIP-39 The Mnemonic Code standard is introduced, revolutionizing UX. Complex keys are statistically represented using 12-24 words from a standardized dictionary of 2048 terms.
2014 | BIP-44 Standardizes the derivation paths for multi-account HD wallets (e.g., m/purpose'/coin_type'/account'/change/address_index), resolving collisions between different blockchains in the same wallet.
2015-2016 | Keccak vs SHA-3 & EIP-55 NIST standardizes SHA-3 (based on Keccak). Around the same time, Ethereum is born and adopts the original Keccak (not NIST's SHA-3, which altered the padding and domain-separation). In 2016, Vitalik Buterin introduces EIP-55, a backward-compatible trick to add a checksum to historically "flat" Ethereum addresses.

5. Statistical Properties & Probabilities

To directly address the statistical properties of the pipeline, here is a purely probabilistic analysis of the involved cryptographic primitives:

BIP-39 (Mnemonic Entropy)

A 12-word phrase is drawn from a standardized dictionary of 2048 words. The possible combinations are $2048^{12} = 2^{132}$. After subtracting 4 bits for the checksum, 128 bits of pure entropy remain. Statistically, generating or guessing another user's active phrase is equivalent to finding a specific atom in the observable universe: the probability of a random collision is virtually zero.

Keccak-256 (Collision Resistance)

The 256-bit output of the Keccak hash function acts as a Random Oracle. Due to the Birthday Paradox, the statistical probability of finding two different Public Keys that produce the exact same 20-byte Ethereum address (a collision) requires attempting approximately $2^{80}$ hashes (since the address is truncated to 160 bits). It remains computationally infeasible.

EIP-55 (Typo Detection Probability)

The EIP-55 checksum uses the 40 nibbles (half-bytes) of the hash to determine the capitalization of the address string. On average, a 40-character hex address contains 15 alphabetic letters (a-f). The statistical probability that a mistyped address randomly generates the exact same valid uppercase/lowercase pattern is $(1/2)^{15}$, or about 1 in 32,000. This means EIP-55 catches 99.996% of human typing errors.
